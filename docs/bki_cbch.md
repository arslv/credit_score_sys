# БКИ: Спектрум Бюро (cbch.ru) и ручной запрос отчёта

## Как работает запрос сейчас

- Стадия Б проходит дешёвые проверки (полнота, шариат, лимиты, поручитель) и
  останавливается в статусе `awaiting_bki` («Ждёт запроса КИ»). В CRM в это
  время ничего не уходит.
- В карточке заявки сотрудник (`operator` или `admin`) выбирает вид отчёта —
  две кнопки из `bki.report_types` в правилах:
  - **Обычный** — у бюро это «информационная часть КИ» (`reportCode` 2): заявки
    клиента в другие организации и отказы, **без кредитов и платежей**.
    Долговую нагрузку по нему не посчитать, поэтому одобрить по нему нельзя
    (`allows_approval: false`) — только «решение за оператором».
  - **Подробный** — полный кредитный отчёт (`reportCode` 1): кредиты,
    платежи, просрочки. Дороже.
- Заказ пишется в `bki_request_orders` и `audit_log` (кто, какой отчёт), дальше
  фоновая задача делает запрос, и решение уходит в CRM как обычно.
- Сохранённый отчёт младше `bki.cache_days` используется повторно бесплатно:
  для «подробного» — только подробный; для «обычного» подходит любой.
- `BKI_REQUEST_MODE=auto` — прежний режим без кнопок (тесты, демо).

Соответствие «обычный = информационная часть» — наше предположение по
документации бюро; подтвердить у заказчика.

## Что нужно для подключения к бюро

У бюро нет HTTP-API: обмен файлами.

1. Договор с бюро и учётная запись (личный кабинет `chd.cbch.ru`).
2. Квалифицированная электронная подпись организации (ГОСТ Р 34.10-2012) и
   **КриптоПро CSP 4.0/5.0** на нашем сервере — запрос подписывается
   (CMS/PKCS#7, DER).
3. Защищённый канал **КриптоПро NGate** до SFTP бюро (настраивает бюро вместе
   с нами): запросы кладём в `inbox`, квитанции и отчёты забираем из `outbox`.
4. Формат: запрос — XML (UTF-8, `requestInfo` / `agreement` / `subjectInfo`),
   упакованный в ZIP и подписанный, имя `ГГГГММДД_NNNNN.zip.sig`; отчёт — JSON
   (`header`, `body.title`, `body.main`, `body.info`). Нужна XSD запроса от
   бюро — на сайте её нет.
5. Ответ асинхронный — отчёт появляется в `outbox` позже; у нас для этого уже
   есть ожидание с защитой от двойной оплаты (`bki_requests_in_flight`).

Пока этого нет, `BKI_PROVIDER_MODE` — `not_configured` (после кнопки —
«БКИ не подключено, решение за оператором») или `fake` для проверок.

Документация бюро: https://chd.cbch.ru/docs/about/overview (порядок
направления запросов, формат кредитного отчёта). Контакты: b2b@cbch.ru,
8 (499) 455-65-60; техподдержка supportb2b@cbch.ru.

## Подключение: полный автомат (решение владельца, 31.10.2026)

Ключ организации ставится **на сервер**: КриптоПро CSP + контейнер ключа на
сервере, подпись делает сервер. Сотрудникам на своих компьютерах ничего
ставить не нужно — они только нажимают «Запросить КИ» в карточке.

**Сделано** (`app/sources/cbch.py`, тесты `tests/test_sources_cbch.py`):
сборка XML-запроса по примеру бюро, упаковка в ZIP с именами
`ГГГГММДД_NNNNN.zip` / `_R.xml`, подпись утилитой `cryptcp` по отпечатку
сертификата (на тестах — заглушка вместо КриптоПро).

**Дальше (код):** отправка пакета на SFTP бюро через NGate, опрос `outbox`,
разбор квитанции, ожидание отчёта без повторной оплаты (заявка ждёт в
`awaiting_bki`, отчёт подхватывается, когда придёт), разбор отчёта в наши
показатели (ПДН, просрочки, балл).

**Нужно от владельца / бюро:**

1. Сертификат КЭП организации с **экспортируемым ключом** (или отдельный
   токен, который будет постоянно вставлен в сервер). Ключ на защищённом
   токене (Рутокен ЭЦП 2.0, JaCarta ГОСТ и т. п.) скопировать на сервер
   нельзя — тогда нужен отдельный сертификат для сервера (сотрудник с
   машиночитаемой доверенностью, в коммерческом УЦ).
2. Лицензия и дистрибутив **КриптоПро CSP 5.0 для Linux** (сервер) —
   скачивается с cryptopro.ru под учётной записью.
3. От бюро: настройка **NGate** (клиент/сертификаты для сервера), адрес и
   учётная запись **SFTP**, сертификат бюро.
4. От бюро: полный **формат кредитного отчёта** (раздел 4 «Формат КО», JSON) и
   формат квитанции — в открытой документации их нет; лучше с примерами
   файлов из тестового контура.
5. Подтвердить у бюро: цель запроса для рассрочки (по справочнику — 9 «иной
   потребительский договор»), срок согласия (`termCode`), присоединённая или
   открепленная подпись (в документации противоречие), есть ли тестовый
   контур.

Пароли, PIN и ключи — только в `.env` на сервере, не в чат и не в git.
