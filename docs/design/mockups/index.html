Карточка заявки — 3 состояния

  • Одобрено — честная подпись балла БКИ, порог на шкале, без выдуманной карты факторов
  • Отказ по стоп-фактору — санкционное совпадение, «нужно сделать» ведёт в комплаенс
  • Серая зона — ФССП не проверено — балл сам по себе не в серой зоне, причина другая, это видно сразу

Остальные экраны

  • Список заявок — быстрые фильтры, «нужно действие», решение вместо сырых стадий А/Б
  • Скоринг — формы вместо YAML, симуляция, экспертный режим свёрнут
  • Аналитика — заголовки-выводы, распределение балла БКИ с порогами (не выдуманные факторы)
  • ⚠ Будущее (T18) — скоринговая карта по факторам — отдельно, явно помечено, не часть текущего состояния

Что учтено из аудита (шаг 1), но НЕ показано отдельным макетом

  • Коды → подписи (решения/статусы/роли/действия аудита/причины/реестры) — один словарь в lib/labels.ts, Badge без подписи падает в тесте. Это код и тесты, не макет — делается на шаге 3 (реализация), в макетах выше везде уже подставлены подписи вручную, чтобы макет честно показывал целевой вид.
  • Бейдж «Активен» на странице сотрудников (раньше показывал код статуса заявки) — уже исправлен в коде, не макет.
  • Аудит — «Объект» ссылкой с человекочитаемым названием (номер заявки для admin, ФИО для ролей с ПД) — экран «Настройки → Аудит» в основном переиспользует текущую таблицу с другим рендером ссылки, отдельный макет не делала (риск несоразмерен пользе на этом шаге).
