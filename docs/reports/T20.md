# T20 — финальная полировка интерфейса

Стиль: строгий, минималистичный. Логика решений не менялась — ни одной
строки в `app/engine/*`; бэкенд-изменения только в отображении карточки
(новые поля ответа) и в консольной команде создания сотрудника.

## Принципы — как реализованы

- **Токены в одном месте** — `frontend/src/index.css`, `:root`: шкала
  отступов (4px-сетка, `--space-1…7`), шрифтов (`--font-xs…xl`), высоты
  кнопок/полей (`--control-height`, `-sm`), цвета. Светлая и тёмная тема.
  Инлайн-стили с пикселями убраны со всех экранов (остались только два
  вычисляемых: позиция маркера на шкале балла и ширина бара).
- **Белый фон, один акцент** (ссылки, главная кнопка, активный пункт меню).
  Цвет статуса — только точка (статусы в списке и истории, «В норме»,
  итог «Состояния системы») и тонкая полоса слева у вердикта. Цветные
  плашки статусов, бежевая/оранжевая заливка вердикта и панели «Нужно
  сделать», цветные плашки источников (T16) — убраны.
- **Меньше карточек**: `.card` и новая `.section` — заголовок + тонкая
  линия сверху, без рамки и фона. Таблицы — без коробки, только линии строк.
- **Подсказки «?»**: компонент `Term` удалён целиком (карточка, Аналитика,
  Скоринг, Справка). Осталась одна — у вердикта карточки (`VerdictTitle`),
  по клику, с объяснением именно этого решения из `lib/explain.ts`,
  например: «Серая зона: балл 760 выше порога 700 и ПДН 42% в пределах 60%,
  но ФССП не проверено — без этой проверки одобрить нельзя.» Пояснения,
  которые раньше были в подсказках на Аналитике и в Скоринге, — обычным
  мелким серым текстом рядом.

## Карточка заявки

1. **Баг «Сработавшие стоп-факторы» с пройденными проверками.** Сравнения с
   порогами (балл, ПДН) рисовались той же красной строкой `rule-hit`, что и
   сработавшие правила. Теперь `explainDecision` (`lib/explain.ts`) делит:
   строка причины — один раз, в вердикте; «Причина» — только детали, которых
   там нет (остальные сработавшие правила, проваленные сравнения, которые не
   сама причина); «В норме» — пройденные сравнения, мельче, серым, зелёная
   точка. Тесты: `e2e/application-card-reasons.spec.ts` (чистая функция на
   одобрение / серую зону / отказ по баллу / отказ по стоп-фактору + карточка
   в браузере).
2. **Баг «ПДН 0%».** Проверил путь: доход и платежи из `/review` (T18)
   доходят — `income.declared_monthly` в знаменатель, `obligations.
   monthly_payment_total` — в заявленный ПДН (фильтр до БКИ). Фактический
   ПДН по ТЗ считается по **действующим кредитам из КИ**; у фейкового БКИ
   по умолчанию только закрытый кредит → честные 0%, но выглядело как
   ошибка. Сделано:
   - бэкенд отдаёт `pti_status` (`computed` / `no_income` /
     `no_credit_history`) и `bki_active_contracts_count`;
   - нет дохода → «ПДН: не вычислимо (нет данных о доходе)»; решение без КИ
     → «… (кредитная история не получена)»; 0% при доходе → «ПДН 0% —
     действующих кредитов в КИ нет (порог 60%)».
   Тесты (`tests/test_engine_stage_b.py`): `/review` с доходом 100 000 и
   платежами 15 000 → declared_pti 0.15, ПДН 34% по трём кредитам КИ,
   `computed`; доход 0 → `pti=None`, `no_income`; БКИ не подключено →
   `no_credit_history`. Playwright: карточка без дохода — нет «ПДН 0%».
3. **«Нужно сделать»** — одна строка с главной кнопкой сразу под вердиктом
   («К проверке ФССП», «Открыть комплаенс»), без рамки.

Попутно в карточке (то, что было видно на скриншотах):
- до `/review` у заявки заглушки сделки T18 (цена 0, срок 0, тариф
  `unknown`) — карточка показывала «0 ₽ на 0 мес., тариф «—»»; теперь эти
  строки скрыты, пока сделка не пришла;
- «Передано оператору» в истории — нейтральная точка (янтарный только у
  серой зоны, как в списке с T17);
- «первый взнос от …» одобрения перенесён в строку «Одобрено» блока
  «Сделка» (раньше дублировал её под «Почему»).

## Состояние системы

Сверху строка-итог: «Всё работает» (зелёная точка) или «Есть проблемы: N»
(красная) и список проблем: что случилось и что делать (`lib/health.ts`).
Все счётчики, версия правил, реестры — в свёрнутых «Подробностях».
Проблемой считается то же, что раньше красило строку; реестр МВД — нет
(источник отменён в 2023, всегда «устарел», см. T17). Тесты:
`e2e/system-status.spec.ts`.

## Допущения и открытые вопросы

- **Цвета источников (T16, ваше решение)** убраны ради «одного акцента» —
  источник теперь просто подпись. Если цвета нужны — вернуть одной правкой
  `SourceBadge`.
- **Точки «нужно сделать» в списке** — акцентный цвет для всех видов
  (были разные: звонок/ФССП/комплаенс), серая зона — янтарная, «проверить
  изменение» — серая. Вид действия читается из текста рядом.
- **ПДН по ТЗ — без платежа по новой рассрочке и без заявленных клиентом
  платежей** (только действующие кредиты из КИ). Это поведение движка, не
  менял («логику решений не трогаем»); если ПДН должен включать будущий
  платёж — отдельная задача на правила.
- Справка: текст «забирает заявки через их API» (до T18) заменён на push-схему.
- На стадии Б отказов в dev-базе нет — скриншот «отказ» сделан на отказе
  стадии А (совпадение по перечню).
