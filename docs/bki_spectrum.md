# БКИ через Спектрум Дату

У заказчика есть кабинет Спектрум Даты с двумя пакетами — это две кнопки в
карточке заявки (`bki.report_types` в правилах, `app/sources/spectrum.py`):

| Кнопка | Пакет | Что внутри |
| --- | --- | --- |
| Обычный | «Кредитный рейтинг» | блок `P.0191.CRR.HIS`: балл 0–999, текущая и максимальная просрочка, число кредитов, средний платёж, лимит, обращения в бюро за 7/14/30 дней, безнадёжный долг |
| Подробный | «Проверка соискателя — Премиум» | тот же кредитный рейтинг и ~30 проверок: ФССП, банкротство, паспорт (недействительные), ИНН, самозанятость, террористы и экстремисты, суды, розыск… |

## Как используем

- Запрос — только по кнопке сотрудника (`BKI_REQUEST_MODE=manual`), каждая
  проверка списывается из пакета.
- Кредитный рейтинг → балл, ПДН и признаки просрочек для правил. Суммы и
  количества у бюро — диапазонами; какую границу брать — `bki.range_bound`
  (по умолчанию верхняя, осторожнее). «Средний платёж» считаем платежом по
  всем действующим кредитам в месяц — проверить на первых настоящих ответах.
- Проверки из подробного пакета пишутся в `bki_bureau_checks` и показываются
  в карточке рядом с нашими с пометкой «БКИ». **В решение не входят** — наши
  проверки (ФССП с капчей, банкротство вручную…) идут как обычно.
- Сырой ответ бюро — в `bki_reports.report_raw.raw`.

## Подключение (API)

Асинхронный B2B-API, описание — Swagger
https://b2b-api.spectrumdata.ru/swagger-ui/index.html
(`app/sources/spectrum_http.py`):

- заказ — `POST /b2b/api/v1/user/reports/{report_type_uid}/_make`, тело
  `{queryType: MULTIPART, query: " ", data: {...}}`, в ответе uid отчёта;
- результат — `GET /b2b/api/v1/user/reports/{uid}?_content=true&_detailed=true`,
  готов, когда `progress_wait == 0` (ждём до `SPECTRUM_POLL_TIMEOUT_SECONDS`);
- вход — заголовок `AR-REST base64(user:stamp:age:base64(md5(stamp:age:base64(md5(пароль)))))`;
- не дождались — заявка в «серую зону» с кнопкой повтора; uid отчёта лежит в
  Redis (сутки), повтор забирает тот же отчёт, а не заказывает новый.
- метка времени токена ставится на `SPECTRUM_CLOCK_SKEW_SECONDS` (60) в
  прошлое: их часы отстают на несколько секунд, а метку «из будущего» API
  отвергает (`403 S111`);
- ошибка бывает и при HTTP 200 (`{"status": 500, "error": {...}}`), размер
  страницы списков — не больше 100.

Пакеты нашего аккаунта (домен `ip_aliev_b_a`, пользователь API
`user_integration@ip_aliev_b_a`, проверено 02.11.2026):

| Кнопка | uid пакета | Квота |
| --- | --- | --- |

Остаток — `GET /b2b/api/v1/domain/balance` (бесплатно).

## Как включить

1. Получить у Спектрум Даты пользователя API (логин вида `login@domain`) и
   пароль. Вписать на сервере в `.env` (в git не попадает):
   `SPECTRUM_USER=...`, `SPECTRUM_PASSWORD=...`.
2. Проверить доступ (ничего не списывает):
   `docker compose exec api python -m app.cli.spectrum check`.
3. Идентификаторы пакетов уже в правилах (`config/rulesets/dev.yaml`,
   `bki.report_types.*.provider_code`); список —
   `docker compose exec api python -m app.cli.spectrum report-types`.
4. `BKI_PROVIDER_MODE=spectrum` в `.env`, перезапустить api и worker.
5. Одна живая заявка (спишется одна проверка): сверить, что блоки приходят по
   путям из описаний, и проверить допущение про «средний платёж».

Разобраны блоки (`BUREAU_BLOCKS` в `app/sources/spectrum.py`): ФССП (P.0035 —
открытые ИП и долг), банкротство (P.0124), недействительный паспорт (P.0308),
ИНН (P.0031; если наш ФНС ИНН не нашёл, карточка берёт его для поиска на
Федресурсе), самозанятый (P.0247), перечень террористов (P.0043 — с
релевантностью). Остальные блоки пакета, если понадобятся, — по их
описаниям; блок без описания в карточке не показывается.
